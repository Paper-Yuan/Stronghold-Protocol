## 2. 必须知道的四个机制

### 2.1 3D 官方场景：坏在两份清单不一致，不在代码

    stages.json 的 stage.id（act1autochess_m01 …）
      → render/app.js setStage() → useOfficialScene(st)
      → board3d/load.js sceneListed(assets, id)      需要清单里有 scene/<id> 的 scene + bin
      → loadScenePack() 取 scene.json / scene.bin / lm*.webp / scene/tex/*
      → board3d.setScenePack(id, pack)

**关键坑**：服务端发的是 `data/local-assets.json`，而 git 跟踪的是 `public/data/local-assets.json`。
两份不一致时，页面拿到的清单里没有 `scene/*` 组 → `sceneListed` 为假 → 一直画程序生成的方板，
而且**控制台不报错**。现在两份已同步（`count=1658`、`groups=75`、`scene 组=12`）。

设置里的三个档位别混：`2d` / `3d`（内置程序化）/ `3dscene`（官方场景）；只有第三档会去套场景包
（`render/app.js` 里 `if (settings.boardMode === '3d') return;`）。

### 2.2 官方特效（工坊式粒子）的位置

规范路径是 `public/assets/local/fx/`（`index.json` + `textures.json` + `prefabs/` + `tex/` + `mesh/`），
文件清单由 `data/local-fx.json` 提供（`library.js` 走的 `/data/local-fx.json`）。
现在：12406 文件 / 182 MB，清单 `count=9086`。**不要再放到 `public/fx/`** —— 那里客户端一行都不会读。

### 2.3 皮肤挂载点

`index.json` 的 `skins` 有 509 个皮肤（平均 3.4 个挂载点，45 种名字，最多 16 个）。
`render/vfx/wiring.js` 的 `skinOf()` 先按皮肤 id 查、查不到按 charId 回退。
皮肤立绘/头像走的是 `data/assets.json` 的 `chars[charId].skins[skinId]`，与这里的挂载点是两回事。

### 2.4 工坊层文档现在有正文了

`docs/design/mod-layer.md` = `DESIGN §34`，20 节：身份与摘要、装载期拒绝、`forms`/`fx.silentPhases`、
`server.transport`、作者 CDN（语音 + 容器镜像）、core-first 路由、`variants`/`behaviour`/`form` 三张声明表、
`morphPairing`、`target`、`mod-registry`、依赖与互斥、`trait.grantsBonds`、`enabled`、`skins[]`、`healthz`。

代码里原本写的是 `§28.x`（草稿编号，和 0.2.3 的发布说明撞号）；现在已改到 `§34.x`。
**还剩 `§28.1–§28.27` 里的一部分工坊引用指向 0.2.3**（见 5.3）。

## 5. 已知问题（按该修的顺序）

### 5.1 【P0】test/client-static.test.js 跑不完

现象：打印到 `identity (reconnect-token selection across tabs)` 的第三条 ✔ 之后**不再前进、也不退出**
（`node --test` 一直挂着，进程还在）。干净环境（无其它测试进程）同样复现，不是并发争用。
按名字过滤跑是**全绿**的：

    node --test --test-name-pattern="constants.js and protocol.js|static import graph" test/client-static.test.js
    → tests 297 / pass 297 / fail 0

因为 `npm run ci` 的第一步就是 `node --test`，**整个 CI 会卡在 test 步**。建议下一步：
用 `--test-name-pattern` 二分 `identity` 之后的 `data.js` 套件；重点看 `createIdentity` 的
`queryMs` 轮询有没有留下未清理的定时器/通道（三个 identity 用例里有几个 `channel` 没有 `close()`）。
