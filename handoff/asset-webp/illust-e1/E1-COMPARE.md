## 0. 结论

1. **q90 可接受，建议定为正式档位。** 24 张实测聚合压缩比 3.85× / 5.43× / 5.35×（小/中/大三档）；按对数分段外推，整目录 717.06 MiB → **136.77 MiB**，省 **580.29 MiB（80.9%）**。
2. **792×360 手机屏上不可辨。** 整幅铺满屏宽（792 px）时 PSNR **42.7–47.5 dB**、SSIM **≥0.9919**；卡片实际尺寸（整图缩到 360 px 高）PSNR **47.9–52.0 dB**、SSIM **≥0.9994**。
3. **但 DPR=3 是真实的例外。** 792 CSS px 的屏在 DPR=3 时有 2376 个设备像素，此时 q90 的 PSNR 回落到 **38.8–42.9 dB**，最大那张等于全分辨率 38.2 dB：属于「肉眼干净、但不是无损」，细看+并排 A/B 能找到发丝/高光边缘的轻微软化。
4. **alpha 零损失**：`alpha_quality=100`，4 张样本的 alpha 平面与 PNG **逐像素完全一致**（maxdiff = 0）。透明边缘没有毛边、没有半透明台阶。
5. **`exact=True` 有代价**：它保留全透明像素底下的 RGB，4 张样本上 q90 文件因此大 **+2.3%~+8.2%**（§5.1）。纯前端展示不需要它，去掉可再省 2–8%。
6. **档位建议**：正式用 **q90**；若带宽吃紧，**q85** 可接受（只降 1.3 dB，体积再小 17.4%）；**q80 不建议**——最大那张在 DPR3 下掉到 36.5 dB，是可指认的退化。

## 5. 外推：整目录 233 张全转 q90 的总量与节省

**方法：对数分段映射（逐张计算，不用任何平均比）**

```
c_t = 各档 8 张字节的几何平均        # 体积的"位置"
    = 453,703 / 2,990,464 / 8,143,149 B
r_t = 各档聚合压缩比 Σ原 ÷ Σ新        # 字节加权，比逐张平均更贴近整目录口径

对每个文件 v（共 233 个）：
    x = ln(v)
    r(v) = 在 (ln c_min, ln c_mid, ln c_max) 三点间对 r 线性插值；x 超出两端时取端点值（平延）
    输出 += v / r(v)
```

| 档位 | 逐张插值外推 MiB | 节省% | 全目录节省 | 对照：平均比硬乘 | 平均比偏差 |
|---|---|---|---|---|---|
| q90 | **136.77** | **80.9%** | 580.29 MiB | 142.84 | +4.4% |
| q85 | **113.01** | **84.2%** | 604.05 MiB | 117.97 | +4.4% |
| q80 | **98.05** | **86.3%** | 619.01 MiB | 102.43 | +4.5% |

三档分段比值（小/中/大）：q90 = 3.85 / 5.43 / 5.35；q85 = 4.62 / 6.51 / 6.54；q80 = 5.23 / 7.47 / 7.58。

**外推结论**：整目录 717.06 MiB → q90 **136.77 MiB**，省 **580.29 MiB（80.9%）**。

作为对照，把 24 张的平均压缩比直接乘总量得到 142.84 MiB，比逐张插值**多算 6.08 MiB（+4.4%）**，也就是**低估了同样的节省量**。原因是目录里 83 张小图的压缩比只有 3.85×，但它们在「平均比」里和 5.4× 的大图等权——平均比被小图拉高，而体积却集中在大图。**这就是不能用平均比硬乘的原因。**

### 7.3 在 792×360 手机屏上是否可辨？

判定依据三条，一起看：

1. **PSNR**：8 bit 图像的经验线是 40 dB ≈ 不可辨、45 dB ≈ 视觉无损。792 px 宽档 4 张为 **44.8 / 47.5 / 42.7 / 43.8 dB**，全部显著高于 40 dB → **通过**。
2. **SSIM**：≥0.99 结构性差异不可见，≥0.999 基本无感。792 档最低 **0.9919**（`char_605_cmedic`，且它是 356 px 原生被上采样到 792），其余 ≥0.998 → **通过**。
3. **局部最大差**：maxΔ 达 24–60 个灰阶，看起来吓人，但这些尖峰**只落在高对比发丝/高光边缘的个别像素**；|Δ| ≥ 4 的像素仅占 5.1%–15.4%，其余 85% 以上像素差异 ≤3 阶（≈1.2% 亮度，低于手机在正常观看距离下的 JND）→ **通过**。

**判断：在 792×360 的显示尺寸下，q90 不可辨。** 真机上要看出差别，需要同时满足「把立绘放大到接近 1:1 原生分辨率」和「与 PNG 并排快速 A/B 切换」两个条件。

**必须说清的反例（DPR）**：792×360 是 **CSS 逻辑像素**。DPR=3 的机器有 2376×1080 物理像素，若立绘铺满屏宽，q90 实际是**以 2376 px 宽呈现**的——此时 PSNR 38.8–42.9 dB、SSIM 0.9928–0.9950，最大那张等同于全分辨率的 38.2 dB。**这一档不属于「完全不可辨」，属于「细看能找到、正常看不影响」**。如果目标机型是 DPR 3 且立绘会全屏展示，这是唯一需要认真对待的场景，也是不建议降到 q80 的直接原因。

透明占比（`全透明%` 列）：


PSNR / SSIM（先合成到中性灰，再比）：

```python
a = np.asarray(im.convert('RGBA'), dtype=np.float32)

flat = a[:, :, :3] * al + 128 * (1 - al)        # 合成到 #808080

# SSIM：亮度通道，11x11 高斯窗 sigma=1.5，C1=(0.01*255)^2 C2=(0.03*255)^2
# 用 FFT 做二维卷积（大图内存友好）：

```

对数分段外推（对应 §5）：

```python
c = [exp(mean(log(v) for v in tier)) for tier in tiers]   # 三档几何平均
r = [sum(v for v in tier) / sum(out(v) for v in tier) for tier in tiers]  # 三档聚合比
total_out = 0
for v in all_233:
    x = log(v)
    rf = interp(x, [log(ci) for ci in c], r)   # np.interp 语义：两端平延
    total_out += v / rf
```
