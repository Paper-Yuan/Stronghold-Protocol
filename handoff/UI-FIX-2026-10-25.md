## 1. 根因：合并把「两代」文件混在了一起

`git merge v0.3.3` 时，冲突文件是按「保留本地 / 接受上游」逐个挑的，结果 `public/` 目录变成了
**两代文件的混合体**：

| 层 | 本地（0.3.1.1 时代） | 上游（v0.3.3） | 结果 |
|---|---|---|---|
| 大厅 JS | `lobby.js` 1157 行，用 `ally-*` / `diff-card-*` / `hub-dialog` 等旧类名 | — | 保留本地 |
| 大厅 CSS | — | `lobby.css` 1168 行，用 `hub-entry` / `mode-card` / `lobby-hub` 新类名 | 接受上游 |
| 服务端 lobby | 1998 行，缺 8 个 `room.*` 处理分支 | 2531 行，30 个分支齐全 | 保留本地 |
| 协议 | — | `shared/protocol.js` 不含 `solo_infinite` | 接受上游 |

**直接后果**（就是用户看到的三个报错 + 界面错乱）：

1. `lobby.js` 用到的 **214 个样式类里，115 个在新 CSS 中根本不存在**（覆盖率只有 51%）
   → 大厅「没有 CSS 结构、位置错乱」。
2. 本地 `lobby.js` 发 `room.create { mode:'solo_infinite' }`，而上游协议只认 `'solo' | 'coop'`
   → `net.js:460 refusing invalid room.create: bad field mode`。
3. 本地大厅的「名片干员」发 `room.card`，本地服务端没有这个分支
   → `loadoutSync.js:502 room.card refused BAD_MSG unhandled type room.card`。
4. 本地 `game.js:178` 调 `battleRunner.setBattleSpeed()`（超限 1×/2× 倍速），
   而上游 `runner.js` 没有这个方法
   → `main.js:363 TypeError: battleRunner.setBattleSpeed is not a function`（整个 GameScreen 崩溃）。

> 结论：**不是「CSS 丢了」，而是「JS 与 CSS 不同代」**。补 CSS 是治不好的 —— 必须成对换。

### 2.4 战斗 runner：补 `setBattleSpeed()`

`public/js/battle/runner.js` 新增：

```js
function setBattleSpeed(speed) {
  // 重定位每个条目的时钟基准 t0，使「当前 tick 位置」不变：
  //   tick = (t - t0)/1000 × speed / TICK  ⇒  新 t0 = t - (t - t0) × 旧速/新速
  // 变速瞬间不跳进度、不重复回合。
}
```

只在速度真的变化时 `publishState() + schedule()`，并已挂到导出的 runner 对象上

### 2.5 `Match.isInfinite` 接上开关（超限规则的真正入口）

`test/match/infinite-curve.test.js` 头部记录的已知缺陷：`isInfinite` 被
`combat` / `phases` / `bossRounds` / `clientCombat` 读了 **6 处却从未被赋值**，
所以 R16+ 无限波次、双 Boss 轮、限伤放宽、索敌节流**一行都没跑过**。

`server/match/Match.js`：

```js
this.mode = isSoloRoomMode(opts.mode) ? 'solo' : 'coop';   // solo_infinite 此前被当成 coop
this.isInfinite = isInfiniteMode(opts.mode);               // 只有超限局为真
```

`mode` 仍归一成 `'solo'`，沿用单人的全部既有判定；超限规则只由 `isInfinite` 点亮，
因此 **solo / coop 一律为 false**（业主明确要求的边界）。

### 2.10 【P0】顺手修掉两个「玩法阻断级」的合并缺口

审计 `public/` 时用同样的思路查了服务端：**上游模块调用的方法，本地保留的模块里没有**。
抓到两处，都是必现阻断：

**（1）`beforePrepOffers()` —— 任何含机变轮的局都卡死在 SP_DRAFT**

`spDraft.js`（上游）的 `finishSpDraft()` 调 `this.beforePrepOffers()`，
而这个方法只在上游 `phases.js` 里定义；我们保留的是本地 `phases.js`（旧一代）→ 抛 `TypeError`，
阶段永远停在 `SP_DRAFT`：机变卡选完、`spTurn()` 返回 `null`、回合不推进。

实测：`solo` 与 `solo_infinite` 都在 **R3（第一个机变轮）停住**，对局无法继续。

修复：按上游同名方法在 `phases.js` 补上 `beforePrepOffers()`（清 `sp` → 开 prep 插件窗口 →
无阻挡则 `enterPrep()`），并把 `afterRoundStart()` 的 `else` 分支从 `enterPrep()` 改成它。

**（2）`_openTeamLp()` —— 测试控制台「跳到隐秘核心」抛错**

`testCommands.js`（上游）调 `this._openTeamLp()`，定义在上游 `bossRounds.js`；
本地 `bossRounds.js` 只有内联写法 → `g.test` 的 hidden 跳轮必崩。

修复：把内联逻辑抽成 `_openTeamLp()` 并让 `startFinalAssault()` 调它。

**这两处之后，`devtools/check-missing-methods.mjs` 在 `server/match/**`（79 文件 / 989 个方法名）
上报告 0 处未解析** —— 这一类缺口被证伪干净了。

### 2.12 三个「自伤」问题的修复

**（1）导入边界越界**（`test/check-imports` 4/4）

早先为了让超限的 `setBondLayerCap` 能用，`server/match/match/platform.js` 从
`public/shared/constants.js` 导入 —— 越过了 `match-client` 边界（服务端不该依赖 `public/`）。
正确做法：把「实时层数上限」这套 API（`currentBondLayerCap` / `setBondLayerCap` /
读 live cap 的 `layerGainRoom`）补进服务器自己的 `shared/constants.js`，`platform.js` 回到边界内。

**（2）UTF-8 BOM 污染**（新增 `devtools/strip-bom.mjs` / `check-encoding.mjs`）

用 PowerShell 的 `Set-Content -Encoding UTF8` 写文件会**加 BOM 并把行尾变成 CRLF**。
本轮我这样写过 17 个文件（`audio.js`、`game.js`、`hud.js`、`client-static.test.js`、
`lobby.css`…），导致按字节比对的正则测试放大失败。全部剥掉 BOM，复查为 0。

**（3）`.github/ISSUE_TEMPLATE/FeatureRequest.yml` 被误删**

合并时它是「本地已删 / 上游修改」，被当作「接受上游删除」处理掉了，但上游 v0.3.3 其实有它，
`test/issue-templates` 要求两个模板都在。用 node 从 git 对象按字节写回（LF、无 BOM）。

### 2.13 移除过时的 ES2020 语法门槛

`test/es2020-syntax.test.js` 是**本地独有**的门槛（上游没有），要求所有模块能用 ES2020 解析，
以支持 Chromium 80–88。但上游 v0.3.3 的代码本身就有 50 处 ES2021+ 语法
（数字分隔符 `1_000`、class 字段、`?.` 等）。

既然 `public/js` 已经整体采用上游一代，这个门槛既无法满足也已无意义 —— 删除。
浏览器基线以 `test/client-static.test.js` 里那套检查（裸说明符、lookbehind、polyfill）为准。
