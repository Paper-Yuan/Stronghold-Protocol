# 桌面端（Electron）· 连接模式与窗口体验

> 角色：连接模式与窗口体验。范围只有一件事——**用户看到什么、点什么**。
> 不覆盖：打包形态 / asar / 自动更新 / 签名（见 `packaging.md`）、主进程起服务方式 / 端口探测 / 数据目录改造（见 `local-server.md`）。
> 本文是新文案的唯一来源；文案只列字面量，**不写进代码**（按仓库规矩：新 `t('…')` 需逐条确认后再落，见 §7）。

调研依据都写在正文里，行号对应当前工作区文件。

## 0. 结论摘要

1. **手机端不是「本地 / 服务器」两栏，是「三卡」**：`单人游玩`／`开服做房主`／`去加朋友`
   （`android/app/src/main/res/layout/dialog_server_switch.xml:99-210`）。本质只有两种连接形态（本机引擎 / 别人的引擎），
   ①②都跑本机引擎，差别只是「要不要把地址交给同伴」（`docs/START-MODES-PLAN.md:3`，代码见
   `MainActivity.kt:1185-1191`）。桌面端必须沿用这三张卡的**同一批字面量**，再加左「本机」右「服务器」两栏字段。
2. **入口形态选①「独立启动页，每次启动先问、预选上次那一档」**（= 手机端现状，`MainActivity.kt:232-234`），
   再把「这次别再问了」做成一个开关（**记住这一档并直连**，默认关）——即③只作为可选项存在，不是默认行为。
   理由：三档是**角色**不是传输（`docs/START-MODES-PLAN.md:3`），换场景频繁；桌面端要建启动页本来就是为了「换档」
   （`local-server.md §5.2`：此时还没有 origin，只能用本地页），启动时顺手显示它几乎零成本；而「记住并直连」在桌面端
   唯一的成本是每次多点鼠标，收益只落在「同一台电脑每天只干同一件事」的人身上 → 交给开关，而不是替所有人决定。
   与 `local-server.md §5.3`（同样建议照抄「每次先问」）一致；差异见 §1.3。
3. **桌面端多出来的只有一件事**：手机是壳层原生对话框 + 无网页内入口（`public/js/ui/settings.js` 里没有任何网络分区，
   页面只用到 `AndroidNative.isNativeApp`），桌面端把这张向导做成**同一套 HTML/CSS/i18n 的页面**，
   开机首屏就是它；这样三端（网页 / 手机 / 桌面）文案不会分叉。
   ⚠ 一个必须提前知道的实现约束：启动页在**还没有 origin** 时就要显示（`local-server.md §5.2`），所以它只能是本地页；
   而 Chromium 默认禁止 `file://` 下的 `<script type="module">`（CORS，origin 是 `null`）。要复用 `shared/i18n.js`
   就必须给启动页一个自有协议（如 `app://desktop/`）或把它编成一个内联的普通脚本——**不要**为此关掉 `webSecurity`。
   纯 CSS（`css/theme.css`）与 `public/i18n/*.json` 的静态读取不受此限。
4. **状态词一个都不新造**：连接中/成功/断线/被拒/版本不符全部复用 `title.js:158-159`、`connBanner.js:54-61`、
   `net.js:52-58` 的既有 msgid（见 §3.1）。真正的新词只剩「桌面端自己的动作」：换端口、测试连接、打开文件夹……
5. **唯一必须改口径的一处**：版本不符时网页说的是「客户端版本与服务器不一致，**请刷新页面**」（`net.js:54`），
   桌面端刷新页面没有意义 → 桌面用「客户端版本与服务器不一致，**请更新客户端**」（新 msgid，§7 #19）。
6. **窗口**：默认 1280×720（= 19.2rem × 10.8rem 的设计框，1rem = 66.7px），最小 **792×360**（手机已验收的横屏尺寸），
   绝对下限 768×432（`1rem` 的 40px 地板，`theme.css:140-141`）。**不接管缩放**——用页面自己的
   `界面大小 75–100%` 与 `文字大小 小/中/大/特大`；**不做托盘**（v1）；**单实例锁必做**。
7. **不额外显示「桌面端」标识**：手机端也没有「手机端」角标；平台差异只出现在三处（第三卡副标题、
   诊断信息、以及插件/素材内嵌导致的按钮隐藏），见 §5.1。

### 1.2 三个方案

| 方案 | 用户每一步要做什么 | 优点 | 代价 |
| --- | --- | --- | --- |
| ① **独立启动页（每次先问，预选上次）** | 每次双击 → 看到三卡已预选上次那档 → 点「连接」 | 与手机**逐字一致**；换「今天自己玩／今天开服／今天去别人服」只需一次点击；地址失效时永远有地方改 | 每次多一次点击（约 2 秒）；「双击就该在大厅里」的期待落空 |
| ② 直接进大厅，设置里切 | 双击 → 直接进上次那一档 → 想换时去设置 | 最快 | 首次启动没有「默认档」可用；**本机服务是否要起、起在哪个端口，无法在进大厅之后才决定**（进大厅本身就是连上某个服务器之后的事）；设置里没有这个入口（§1.1 末行），要先补；与手机端流程差得最远 |
| ③ 首次向导一次后记住 | 首启选一次 → 之后双击直达上次那一档 | 首次有决策、之后零打断 | 与手机端行为不同；「我今天是来开服的」要先去菜单再改一档；失败时要靠失败页兜 |

**选①**。③ 不是被否掉，而是被降级成①里的一个开关（§1.3）：
「记住这一档并直连」打开后，行为就等于③，且失败页仍把它拉回启动页。

### 1.3 推荐：① 每次启动先问 + 一个「记住这一档并直连」开关

**流程**

1. **每次启动**：窗口直接显示启动页（三卡 + 两栏），**预选上次那一档**（`MainActivity.kt:1047-1051` 的 `server_role`，
   键名与取值照抄：`server_mode` = `local|remote`、`server_role` = `solo|lan|remote`，`local-server.md §5.1`）。
   副标题按手机端二选一：有上次地址 → `上次连的是 {url} · 点「连接」继续，或换一台`；否则 `选一个进入。每次启动都会先问这个。`。
2. **点「连接」**：按档位起本机服务或导航到目标地址；切换必然重新载入客户端，文案见 §3.6。
3. **想换**：不用等下次启动——菜单栏「重新选择连接…」（§4.8）随时把窗口带回启动页。
   手机端只能靠重启（它的设置入口只出现在加载失败页），桌面端多这一条**不新增概念**，只是把同一张页再打开一次。
4. **开关「记住这一档并直连」（默认关）**：打开后跳过 1 的启动页，直接按上次档位进游戏；失败时**强制回到启动页**
   （不是停在失败页干等），并把失败原因写在地址栏上方。关闭开关即回到①。
5. **首次启动**永远显示启动页，与记住开关无关（此时还没有「上次」）。

**为什么是把③降级成开关，而不是默认关掉启动页**

- 手机每次问的理由在桌面端**成立三分之一**：手机没有别的入口（网页里没有、壳层只在失败页给按钮）→ 桌面有菜单，所以那一半不成立；
  但「三档是角色、换得频繁」（`docs/START-MODES-PLAN.md:3`）这一半成立，而且启动页**本来就得存在**
  （换档时必须回到它；`local-server.md §5.2`：那一刻还没有 origin，只能用本地页）。既然要建，启动时显示它只多一次点击。
- 「双击 EXE → 直接在大厅」的期待由开关满足；不替所有人决定，是因为这个决定的代价不对称：
  默认直连 → 开服的人每天要先去菜单改一档（多两步）；默认先问 → 只玩一种模式的人每天多一次点击（多一步）。
- 开关只有一条持久化事实：`server_role` 已有 + 一个 `autostart`（桌面端自己的 `config.json`，不进 i18n）。

**与手机端的差异（要写进文档，而不是装作一致）**

| 维度 | 手机端 | 桌面端 | 是否算「各说一套」 |
| --- | --- | --- | --- |
| 何时出现启动页 | 每次启动 | 每次启动（默认）；开关打开后仅首启与失败时 | 否：卡名、副标题、地址提示、按钮**同一批字面量**，只有「开关」是新增 |
| 换档入口 | 只有重启；加载失败页的「局域网与画质设置」 | 启动页 + 菜单「重新选择连接…」 | 否：同一张页，多一个打开方式 |
| 关闭/取消 | 启动时无「取消」（`btnCancel` 隐藏），返回键 = 走本机流程 | 启动时同样无「取消」；从菜单打开时才有「取消」= 保留已存选择 | 否：语义照抄 `MainActivity.kt:1162-1165` |
| 其它设置同屏 | 棋盘渲染 / 高刷 / 异形屏挤在同一框右栏 | 桌面不移植（3D/2D 由页面设置面板管；高刷、异形屏是手机硬件概念） | 否：这些不是「连接」概念 |
| 连远程时本机服务 | 前台保活，留着 | **关掉**（`local-server.md §5.4`：桌面没有后台保活，留着只占 3000） | 否：这是实现差异，UI 上不体现（用户看不到「服务还在跑」） |

### 1.4 口径澄清：三卡 + 两栏，不是「两栏二选一」

- **三卡**决定「用谁的引擎 + 要不要给地址」；**两栏**是这三张卡的参数：左栏写本机（端口/局域网/数据目录），右栏写服务器（地址/测试/最近用过）。
  选 ①/② 时右栏整体禁用，选 ③ 时左栏整体禁用（地址栏沿用手机端「只在这一档出现」的行为，`MainActivity.kt:1134-1136`）。
- ①②在代码上**是同一件事**（`MainActivity.kt:1185-1191`：两张卡都写 `KEY_SERVER_MODE = "local"`，只记不同的 `role`）。
  桌面端因此把「②比①多出来的东西」显式化为左栏的一个开关：**「允许同 Wi-Fi 加入」**。
  选① → 开关自动关并置灰（提示「单人游玩不会对外开服」）；选② → 自动开、可手动关。
- 网页端已经有「节点」这一层词（`serverRedirectModal.js`：`节点`／`一键前往`／`当前节点`／`语音支持`／`当前所在`／`查看全服状态站`／
  `暂留本服观望`），官方节点表在 `shared/serverSelection.js:1-4`（`香港服`／`香港 2`）。桌面右栏的「官方节点」直接用这套词，
  **不要另造「服务器列表」**；`ui/serverPicker.js` 目前是返回 `null` 的空实现，别把它当成已有能力。

## 4. 窗口与快捷键

### 4.1 尺寸

尺度依据（`public/css/theme.css:5-7,140-141,165-168`）：布局根 `1rem = clamp(40px, min(100vw/19.2, 100vh/10.8), 240px)`，
设计框 19.2rem × 10.8rem（= 1920×1080 设计 px）；`--t` 是文字尺度（小/中/大/特大），与窗口无关。

| 项 | 值 | 依据 |
| --- | --- | --- |
| 默认内容区 | **1280×720** | 16:9，1rem = 66.67px，与 1080p 下 1920×1080 的构图等比（同一 rem 尺度下的 2/3 采样） |
| 最小内容区 | **792×360** | 手机端验收过的横屏尺寸（`handoff/shots/zhajing-792x360-*.png` 等一整套）；此时 1rem 触到 40px 地板，窄屏规则生效（`devices.css:143` `max-width:767px`、`:167-172` `max-height:460px`） |
| 绝对下限（不可再小） | 768×432 | 1rem 的 40px 地板 × 19.2 / 10.8；再小布局就整体溢出（没有任何测试尺寸覆盖） |
| 是否锁比例 | **不锁** | `.app-root` 是 `position:fixed; inset:0`（`theme.css:278-283`），非 16:9 只会在多出来的方向留背景；宽高比 19.5:9 / 21:9 / 4:3（1024×768）都已有验收截图 |
| 实现细节 | 用 `useContentSize: true` + `setMinimumSize(792, 360)` | 让「最小」指的是**内容区**而不是含边框的窗口，否则 792×360 会被标题栏吃掉 30px 高 |
| 首次出现的居中 | 居中于当前显示器工作区，不要记忆位置到 v1 | 记忆位置是第二阶段（多显示器） |

- DPI：`setSize` 用的是 DIP，Windows 125%/150% 缩放下 CSS px 与设计单位仍一一对应，**不要再乘 DPI**。
- 1rem 上限 240px：4K（3840×2160）→ 200px/rem，全屏正常；只有 >4608×2592 的超宽屏才会停在同尺寸（可接受，不必特殊处理）。

### 4.2 缩放：**不接管**

- 页面已有两套缩放：`界面大小 75–100%`（`ui/screenFit.js:36-40`，只在「文字大小 = 小」时可用）与
  `文字大小 小/中/大/特大`（`theme.css:165-168`）。桌面端再叠一层 Electron zoom 会变成「三重缩放」，玩家分不清哪个在起作用。
- 具体做法：**不注册 `zoomIn` / `zoomOut` / `resetZoom` 菜单角色**；`Ctrl+滚轮` 已被页面主动吞掉
  （`ui/device.js:327`：`wheel` + `ctrlKey` → `preventDefault`），不会误触。
- 想放大 UI 的玩家 → 引导到设置里的「文字大小 / 界面大小」，不新增桌面专属的缩放入口。

### 4.3 全屏

- **F11** → `win.setFullScreen(!win.isFullScreen())`（主进程）。同时页面自带的「全屏」按钮（`ui/device.js:245-253`，
  标题页 `title.js:280`、游戏内 `game.js:2069`）走 HTML Fullscreen，两者最终都是整窗全屏，状态用同一个布尔量，不各记一份。
- 进全屏**不要**顺带改窗口尺寸/记忆窗口大小；退出全屏回到之前的窗口尺寸（Electron 默认行为即可）。
- 全屏与「全屏时保持屏幕常亮」（`ui/settings.js:523`，msgid `全屏时保持屏幕常亮`）无关，那个是页面设置，原样保留。

### 4.4 DevTools

- **F12** 与 **Ctrl+Shift+I** 打开（detached 窗口）；生产包**不在菜单里**暴露「开发者工具」项。
- 不给 Esc 绑任何壳层动作：Esc 在页面里是「关闭/取消」的公共键（`components.js:432` 等十余处），壳层抢它必然打架。

### 4.5 托盘：**v1 不做**

- 不做：关闭窗口 = 退出（并停本地服务）。理由：v1 的定位是「双击就能玩」，托盘会立刻带来三个必须回答的问题
  ——关闭是退出还是隐藏？隐藏后服务还跑吗？开服者关窗口后朋友该不该继续玩？这些答案要跟 `local-server.md` 的停服策略一起定。
- 但**必须**补齐「关窗会踢掉朋友」的确认（§3.6）。
- 第二阶段（若业主要「挂机开服」）：托盘图标 + 菜单 `显示主窗口` / `重新选择连接…` / `停止本地服务` / `退出`；
  托盘提示文案沿用 `本地服务已就绪 · 端口 {port}` 与「卫戍协议 运行中」（`strings.xml:12`）。
  其中 `显示主窗口`、`停止本地服务` 是第二阶段才需要的字面量，**没有**登记在 §7（做那一期时再逐条报）。

### 4.6 单实例锁：**必做**

- `requestSingleInstanceLock()`；第二个实例只做一件事：把已有窗口 `show()` + `focus()`，然后自己退出。
- 理由（都不是洁癖）：两个实例会抢同一个端口；共用同一个 `userData` 会被 Chromium 的 profile 锁挡住；
  两个窗口连同一台服务器时同一身份会互相 `REPLACED`（`net.js:47` / `server/net.js` `CLOSE.REPLACED`）。
- **不注册 `http(s)://` 协议处理器**：邀请链接留在浏览器里打开是正常路径（`?room=CODE` / `#sp-enter=`），
  抢协议会让玩家以为「点链接会开客户端」；桌面端自己能填整条链接（§2.3 地址栏）。
- 第二个实例带参数（将来若有「用桌面端打开某地址」需求）走 `second-instance` 事件转发给已有窗口，不新开进程。

### 4.7 窗口外观

- 标准系统边框 + 标题栏（不做无边框自绘）：一是省掉一整套窗口按钮，二是最大化/贴边/多显示器行为交给系统。
- 窗口标题**跟随页面** `document.title`（`ui/lang.js:174` 设为 `卫戍协议：盟约 · STRONGHOLD PROTOCOL`），
  **不追加「（本地）」/「（服务器）」后缀**：只有单实例单窗口，没有区分的必要；加后缀就是多一条要翻译的文案。

- 图标/任务栏分组沿用安装包图标（`packaging.md`）。

## 5. 与网页版的一致性

### 5.1 要不要额外显示「桌面端」标识：**不要**

- 手机端没有「手机端」角标；它唯一的平台差异是**隐藏两个按钮**（素材下载 / 导入素材包，`title.js:189-192,283-287`），
  理由是「手机上这两个按钮只会白等」。桌面端同理但**要按素材路线取值**（`packaging.md §6` / `local-server.md §6.3`）：
  全量内嵌 → 隐藏；lite + 首启下载 → 保留「下载完整素材」，隐藏「导入素材包」。**这是行为差异，不是徽标**。
- 一旦打上「桌面端」角标，会立刻暗示「桌面端功能更多/更少」，而实际上同房间、同协议、同插件、同数据，没有任何差异。
- 平台差异只允许出现在三处：
  1. **启动页第三卡副标题**：桌面 `电脑开服·局域网联机`，手机 `手机开服·局域网联机`（§7 #3）；
  2. **诊断信息**：`ui/diag.js:309` 现在已经打一行 `browser: {ua}`，桌面端再加一行 `shell: desktop {版本}`（不是界面文案）；
  3. **素材/更新类按钮的显隐**（同上，`title.js` 的 `nativeShell` 判断，桌面端挂同一个开关）。
- 版本号旁边那个 `开发版 · 不稳定，请勿用于公开服务器`（`title.js:312`）是构建属性，与平台无关，照旧。

### 5.2 同一账号 / 房间跨端

| 关注点 | 现状与结论 |
| --- | --- |
| 身份 | 名字在 `localStorage`、重连 token 在 `sessionStorage` + 近期 token 列表（`net.js` 头注释）。**桌面端是独立的存储分区**，所以桌面玩家 = 一台新设备：与浏览器里的同名玩家是两条 session，不冲突 |
| 同桌 | 桌面本地开服后，手机可以照常加入（同 Wi-Fi 填 `http://{ip}:{port}` 或向导里给的 4 位同盟密钥）。反向也成立：桌面加入手机开的服 |
| 房间码 | `同盟密钥` 4 位（`shared/serverSelection.js` 无关；`server/http/appApi.js:44` 注释：4 个大写字母）。两端同一个输入框、同一句 `向同伴索取 {ROOM_CODE_LEN} 位同盟密钥，或直接打开邀请链接`（`lobby.js:726`） |
| 局域网自动发现 | **手机有、桌面没有**：手机靠 `AndroidNative.findRoom`（`AndroidBridge.kt:29-40` + `NetworkUtils.findRoom`）。桌面端 v1 只能手填地址，**不要**在桌面 UI 上出现「正在扫描局域网…」这类文案（没有实现就是假承诺）。若二期要做扫描，先让 `findRoom` 变成桌面也能调的桥方法，再复用同一批文案 |
| 同一身份两处登录 | 一端顶掉另一端：`该身份已在其他页面登录` + `在此页面继续`（`connBanner.js:55-59`）。桌面端不接管这个提示 |
| 版本 | 本地开服时客户端与服务端同包，**必然一致**；连远程时按 `/healthz.version` 判定（§2.4） |
| 语音 | `http://192.168.x.x` 不是安全上下文，`getUserMedia` 会失败（`roomVoiceClient.js:134` 已有文案）。手机同样如此 → **不是桌面端缺陷**，但启动页/帮助里值得一句"语音需要 HTTPS" |
| 插件 / 素材 | 插件是服务端能力，与客户端平台无关；桌面服主装了什么，手机玩家就看到什么。素材内嵌与否只影响首屏速度 |

### 5.3 iOS 这一端没有壳层，正好是判断口径的标尺

- iOS / 平板 / 普通浏览器打开游戏时**没有原生壳**（`public/js` 里只有 `AndroidNative` 这一个桥），所以它们看到的每一句
  都来自页面既有的 msgid。**桌面壳层新增的每一句，要么能在页面/手机上找到出处（§7.1），要么登记在 §7.2**——
  这就是「同一概念同一措辞」的可执行判据：任何一句在 §7 里查不到、又出现在桌面 UI 上的文案，都是新的分叉。
- 同理，桌面端不要为了「看起来像个桌面软件」而重画启动页样式：用 `css/theme.css` 的 token 与组件（`ui/components.js`），
  iOS 上看到的按钮长什么样，桌面启动页就长什么样。

### 8.3 三份之间仍存在、需要 lead 在 `PROPOSAL.md` 里定夺的口径冲突

1. **「本地服务 / 远程服务器」vs 三张卡**：`packaging.md §阶段三 11` 与 `§5` 的候选字面量用前者，手机端与
   `local-server.md §5.1` 用后者。本文主张**界面用三卡**，「本地 / 服务器」降级为两栏标题（§7 #5/#6）——
   否则同一件事在桌面端会出现两套词，正是业主要求「不要各说一套」要避免的。
2. **`正在启动本地服务…` vs 既有 `正在启动本地作战引擎…`**：前者是 `packaging.md` 的候选，后者已在 `strings.xml:3` 用了整个 APK 生命周期。
   本文用后者（少一条 msgid）。
3. **「换一个端口」在②档不可行**：`docs/WINDOWS.md:109` 教的是 `--port 3001`，但手机端扫描器与地址全写死 3000
   （`local-server.md §3.2`、`docs/START-MODES-PLAN.md:43` P1-6）。②档因此只能给「重新检查 / 改用动态端口（自担后果）/ 切到服务器」。
4. **「首次运行可能提示未知发布者」** 是安装包（NSIS）路径的话术；`packaging.md §2.1` 推荐免安装 zip，那句话就不该出现在首次运行。
   归 `packaging.md` 按最终形态决定，本文不登记为 msgid。
