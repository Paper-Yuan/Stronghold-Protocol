### 1.1 三档视口下的角落键（现成约束，别再往上加）

| 视口 | `.gm__corner` 行为 | 余量 |
|---|---|---|
| 1280×720 | 一行 | 尚有 1 颗 |
| 800×360（20:9） | 一行，按钮缩 | 紧张 |
| 667×375（手机横屏） | `wrap-reverse` **两行** | **已满**（第 8 颗会挤到第三行） |

结论（写进提案的硬规则）：**左下角落键一颗都不加**。

### 1.2 顶栏胶囊槽是唯一免费常驻位

`gm__modetools` 只在「锻造器 / 惊变」房渲染（`public/js/screens/game.js` 的 `modeEntry` 条件），
超限局整格空着。它的造型（`.gm__modetools__plate`：绿色细发光边 + 内里黑细线 + 淡青底、
高 28.8px、触控热区 32px）**已经是最终形态**，新方案直接复用它。

```
.gm__modetools（button，热区 32px）
└ .gm__modetools__plate（可见板 28.8px）
   ├ .gm__modetools__cell  ×N     ← 每格 = 图标 + 数字
   ├ .gm__modetools__sep           ← 1px 墨绿内线
   └ .gm__modetools__dot           ← 右上角红点（「有未决事项」）
```

超限局建议的格子内容（**一颗胶囊装三件事**，避免三个方案抢同一个位置）：

```
▐ ∞  3/5 · 猎场  ·  DIVE 1 ▐
  │   │           │        └ 深潜剩余次数（A 方案）
  │   │           └ 本段节点类型（E 方案）
  │   └ 段进度（E 方案）
  └ 超限标记
```

## 3. 浮层骨架：照抄现成的四个

不要新写一套视觉，四套现成骨架各有明确用途：

| 骨架 | 现成文件 | 版式 | 适合 |
|---|---|---|---|
| `.traitov` | `public/js/ui/traitOverlay.js` + `css/screens/traitOverlay.css` | 全屏、三张竖卡、入场动效、选中→文件夹变形 | 需要「仪式感」的三选一（词条） |
| `.ctrov` | `public/js/ui/contractOverlay.js` | 全屏、三张按钮卡 + 底部「不签」 | **段级决策**（契约、取点、通牒）——最省事 |
| `.olarch` | `public/js/screens/settle.js` | 居中信息板、统计三格 + 列表 | 档案、榜单、只读汇总 |
| `.mpop` | `public/js/ui/matchPopups.js` | 2.2 s 盖板（回合 / 阶段） | **只读**过场，不要在上面放可点键 |

## 6. 无障碍与触控（现有做法，照抄即可）

- 每个可点元素带 `aria-label` + `data-testid`；浮层根节点 `role="dialog" aria-modal="true"`。
- 开合的浮层：`aria-expanded` / `aria-controls`（胶囊、pill 现在都有）。
- `Esc` 关闭：A/B/D 的浮层可以关；**E 的取点是必选，Esc 不关**（要在文档里写死，否则渲染检查会点不到）。
- 触控：胶囊内每格 ≥ 32px 热区；`-webkit-tap-highlight-color: transparent` 已有。
- `reducedMotion()` 时跳过入场动效（`.traitov` 已有先例）。

## 7. 渲染巡检清单（新增浮层都要过）

| 视口 | 检查 |
|---|---|
| 1280×720 | 浮层不遮挡「回合 / 阶段 / LP」三件套；三卡等宽对齐 |
| 800×360（20:9） | 浮层不超出视口高度；底部「奖励」行可见 |
| 667×375 | 三卡横排；胶囊不换行；角落键仍两行 |

写法照 `devtools/render-check-overlimit-archive.mjs`（量 rect、断言无横向溢出、断言可点）。
