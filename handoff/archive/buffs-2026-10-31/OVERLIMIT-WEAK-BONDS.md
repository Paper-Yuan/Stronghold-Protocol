## 0. 结论摘要

### 0.1 先说一个必须先拍板的口径问题

`tools/infinite-anchor-pairs.mjs` 的 `bondState()` 把**分档（tier）按「人数」硬算**：

```js
// tools/infinite-anchor-pairs.mjs:198–200（本文件写作期间该脚本正被另一条线改写，行号以 2026-10-31 02:16 版为准）
const bondState = (id, count, layers) => ({
  count, active: true, tier: Math.min(3, Math.max(1, count >= 6 ? 3 : count >= 4 ? 2 : 1)), layers,
});
```

而真机里 tier 是 **「达到了几个 thresholds」**（[bondsMeta.js:23](server/match/bondsMeta.js#L23)、
`tierFor()` [bondsMeta.js:245](server/match/bondsMeta.js#L245)）：8 条大盟约里 6 条（含这三条）的 thresholds 是
`[3, 6]`，阿戈尔是 `[3, 5]`、炎是 `[3, 6, 9]`，所以 **4 人 → tier 1，5 人 → tier 1，6 人 → tier 2**。
脚本的 `count >= 4 → tier 2` 等于「4 人就送 6 人档」。战斗侧 `reached()`（[core.js:75–88](server/sim/content/bonds/core.js#L75-L88)）正是靠
`bondTier >= idx+1` 这个分支放行的，于是**锚只拿 4 格时，6 人档照样生效**。

我用同一套 harness、只把 tier 换成真机规则重跑（R40，同一 roster/分格/木桩/层数）：

| 锚 | 锚定报告口径 Top1 | 真实分档口径 Top1 | 虚高倍数 |
|---|---:|---:|---:|
| 谢拉格 | 129.63M | **16.56M** | 7.83× |
| 阿戈尔 | 51.88M | **4.48M** | 11.59× |
| 萨尔贡 | 40.91M | **5.78M** | 7.07× |
| 维多利亚 | 26.44M | **4.46M** | 5.93× |
| 炎 | 22.02M | **1.89M** | 11.68× |
| 拉特兰 | 13.81M | **2.22M** | 6.22× |
| 叙拉古 | 8.41M | **1.69M** | 4.98× |
| 卡西米尔 | 4.67M | **0.257M** | 18.19× |

（报告口径列与 `handoff/OVERLIMIT-ANCHOR-PAIRS.md` 逐位一致，说明探针口径对得上，只差 tier 这一处。）

**为什么必须先说**：目标「Top1 进 20–40M」是在**报告口径**下定的。真实口径下全表只有 0.26–16.56M，
20–40M 会让这三条直接变成全表最强。所以本文件每个候选都给**两列实测**（真实口径 / 报告口径），
推荐值按业主的目标（报告口径）标定，同时给出真实口径的预期，业主可以二选一。

另外，三条的「13.81M / 8.41M / 4.67M」分别有 **97.6% / 83.9% / 99.7% 的伤害不是自己打的**：
拉特兰那组是谢拉格（靠错误口径拿到的「4 人 6 档」寒霜风）在打，卡西米尔那组是叙拉古在打。
**换句话说：报告里的这三条 Top1，是「搭裆被错误地当成 6 人档」的产物。**

### 0.2 三条的「弱」各是什么性质

## 2. 拉特兰 `lateranoShip`

### 2.1 现状

- `desc`（2 行）：
  - L1 `【拉特兰】干员开启技能获得的弹药量提升（受层数影响）`
  - L2 `<在场6名不同【拉特兰】干员>【拉特兰】干员每消耗1发弹药，所有【拉特兰】干员攻击力提升（有上限）`
- `effectDesc`（2 行）：L1 `…弹药量+{0:0%}（受层数影响）`；L2 `…攻击力+4%，至多+200%`
- `descRaw` / `effectDescRaw` 用 `<@ba.vup>`、`<@autochess.gray>`、`<@autochess.dgreen>6</>`、`<@ba.acrem>` 标记（原样见 §2.4）。
- 超限专属（2026-10-19 `8f2a3ffa`，code-only，**desc 里没有任何体现**）：弹药 600 层封顶、溢出转穿透/攻血、
  每发 4%→8%、上限 200%→700%、实装圣堂殉爆。

### 2.2 为什么弱（用数据说话）

1. **弹药吞吐是硬上限**：4 人 60s 只消耗 **59 发**（8 人满编也只有 242 发）。任何「每发弹药 X」的收益，
   乘出来只有 59X。圣堂殉爆要求 100 发/次 → **Top1 组合里 0 次触发**。
2. **弹药乘区已经封顶**：600 层封顶 → `1+0.05+0.015×600 = 10.05×`，R40 的 L=1650 早就封顶；
   溢出转「每 100 层 +0.4% 无视防御」只有 `floor((1650-600)/100)=10` 步 = 4%，
   而锚定木桩 **0 防御** → 穿透收益 **恰好为 0**。
3. **6 人档在 4 格拿不到**（真实分档）：每发 +8%、上限 +700% 全靠 6 人档；实测强行给到 6 档（LT-B）也只
   2.22M → 2.44M（+10%）：59 发 × 8% = +472%，还没到 700% 上限，且只作用于 4 名拉特兰（占总伤害 5.5%）。
4. **完全没有伤害乘区通道**：拉特兰全靠「弹药量 → 更多发数 → 普攻伤害」，没有 `dmgDealtMul`
   （谢拉格 1.25→×17.85、维多利亚 1.25+0.008L、奥术 1.2+0.01L 都有）。这就是量级差 1–2 个数量级的根因。

**结论**：拉特兰的弱不是「数值低了 2 倍」，而是**「每发弹药」这条路的天花板只有 59 发**。
bb 数值怎么加、6 人档怎么降门槛，都到不了 10^7（见 §2.3 的 LT-A / LT-B 实测）。要进 20–40M，
**必须给它一条与弹药吞吐无关的通道**。

### 3.2 为什么弱（用数据说话）

1. **6 人档就是它的全部引擎**：攻速 buff 是 3 人档，隐匿 + PRD 真伤全在 6 人档。锚只拿 4 格 → 真实分档
   **tier 1**，叙拉古自己贡献 **0.3%**（1.69M 里几乎全是维多利亚 59.8% + 奥术）。报告里的 8.41M 正是
   「错把 4 人当 6 档」的产物。
2. **一旦引擎开起来，封顶是唯一瓶颈**：强行给 6 档后，60s 内 **153 次 proc，153 次全部命中 250 万封顶**
   （`capHit=153/153`）→ 153 × 250 万 / 60s ≈ 6.4M DPS，这就是它的上限。
3. **概率不是瓶颈**：`prob` 8%→16% 实测 **0 增益**（proc 次数仍 153）——PRD 的循环长度由「符合条件的伤害实例数」
   决定，不是由标称概率决定。这条对业主很重要：**别再往概率上加数值**。
4. 报告 §4.3 说它「最不吃搭档（1.1×）、中位数只有基线 0.57×」——真实口径下更极端，
   因为 4 格的叙拉古**根本没有 6 档**，它的中位数是被别的盟约带的。

## 4. 卡西米尔 `kazimierzShip`

### 4.1 现状

- `desc`（2 行）：
  - L1 `每次有干员部署时，【卡西米尔】干员攻击力+20%持续至战斗结束（上限受层数影响）`
  - L2 `<在场6名不同【卡西米尔】干员>【卡西米尔】干员阻挡敌人时每2秒对周围敌人造成120%攻击力真实伤害和0.1秒晕眩，未阻挡敌人时攻击附带30%攻击力的真实伤害`
- `effectDesc`：L1 `…攻击力+20%（至多+{0:0%}）（受层数影响）`；L2 与 desc L2 同（无层数参数）
- `effectDescParams`：1 项（`base_max_atk_when_born` / `max_atk_when_born_per_stack`）
- **没有超限专属加强**（五条里不含卡西米尔），也没有任何 `zj` 之外的超限数值。

### 4.2 为什么弱（机制硬伤，用数据说话）

1. **所有通道都是「攻击力 ×」**：部署叠攻（ATK +%）、脉冲（120% × ATK）、未阻挡附加（30% × ATK）。
   卡西米尔干员的攻击力只有几千 → 单次伤害几千 → **量级天花板 10^5**。
   实测：8 人满编、6 档全开的**单锚基线**也只有 **90.5k DPS**，其中 `bond:kazimierz` 贡献 18k（20%）。
2. **部署叠攻的「上限」根本不是瓶颈**：上限 = 0.5 + 0.01×1650 = **+1700%**，而 60s 只有 17 次部署
   → 实际只到 **+340%**。把每次加成翻倍（`atk_when_born 0.2→0.4`、基础上限 0.5→2.0）实测只 +1.6%（261k vs 257k）。
3. **6 人档脉冲要求「阻挡」**：锚定木桩是 0 速度的静态墙，只有最靠右的 2–3 名干员真的在阻挡，
   60s 内 `bond:kazimierz` 命中 **125 次**、合计 171k（2.8k DPS）。把 120% 提到 240% 也 **无量级变化**。
   ⚠️ **这一项是口径下限**：真实无尽波次里敌人会走向阻挡位，脉冲次数会远高于木桩口径——但即便如此，
   120%×ATK 的**单次量级**仍是几千，靠次数补不到 10^7。
4. **锚定组合里 96.1% 的伤害来自叙拉古**（卡西米尔成员只占 3.9%）。报告里的 4.67M 是叙拉古在 carry，
   而且同样是「4 人被当成 6 档」的产物；真实口径只有 **0.257M**。
5. **它没有层数入口问题吗？** 有入口（部署类特质、机变「玛恩纳的盟誓」+12），但**有层数也没用**：
   层数只进「上限」，而上限到不了 → 层数对卡西米尔几乎是空转。这比「没有层数入口」更隐蔽。

**结论（机制硬伤）**：卡西米尔缺的不是数值，而是一条**与攻击力无关**的通道。要进 20–40M，
只有两条路：(a) 给一条「目标最大生命 %」的真伤（叙拉古已验证的形状，最贴合「真实伤害」的身份）；
(b) 给一条全队伤害乘区（实测 0.3%/层 → 报告口径 27.77M，但真实口径只有 1.53M，且把卡西米尔变成全队乘区，
与它的身份不符）。**推荐 (a)**。

- **预期**：KAZ-F → 报告口径 4.67M → **25.50M**（×5.46），真实口径 0.257M → **21.09M**（×82）。
- **副作用 ①（挂件）**：脉冲只在**阻挡且 6 档（超限下 4 档）**时触发，2–3 格的卡西米尔挂件**不生效**
  → 挂件风险**低**（这是它比 E2 更好的地方）。风险在另一头：真实无尽波次里敌人成堆走向阻挡位，
  一次脉冲命中多名敌人、每名都吃「至多 1000 万」——**真实收益会明显高于木桩口径**。
  建议先按 **KAZ-G（500 万）** 上线，观察一版后再决定是否抬到 1000 万。
- **副作用 ②（普通 / 湮灭 / 炸惊）**：档位判定在 core.js:785 的 `reached(..., 6)` 调用点、
  %最大生命项加在 core.js:793 的 `const amount = scale * m.s.atk;` 之后，两处都在
  `if (!(battle.flags && battle.flags.overlimit)) return;`（新增）之后 → 普通 / 湮灭 / 炸惊不变。
- **副作用 ③（数值安全）**：脉冲频率不变（125 次/60s），只是每次多一次 `min(maxHp×0.1%, cap)` 运算，
  不新增伤害实例、无性能问题；「未阻挡 30% 附加」分支不动。

三条都 gate 在 `battle.flags.overlimit`，普通 / 湮灭 / 炸惊一帧都不变。

### 5.1 推荐方案在回合轴上的走势（实测，两个口径都给）

| 盟约 | 方案 | R20 真实 / 报告 | R30 真实 / 报告 | R40 真实 / 报告 |
|---|---|---|---:|---:|
| 拉特兰 | 现值 | 0.307M / 1.07M | 1.01M / 4.95M | 2.22M / 13.81M |
| 拉特兰 | LT-C（0.1%/层） | 0.507M / 1.76M | 2.16M / 10.64M | 5.89M / **36.60M** |
| 叙拉古 | 现值 | 0.406M / 6.84M | 0.96M / 7.51M | 1.69M / 8.41M |
| 叙拉古 | SIR-A+B | **25.91M / 25.96M** | 26.46M / 26.63M | 27.19M / **27.53M** |
| 卡西米尔 | 现值 | 0.102M / 4.52M | 0.18M / 4.59M | 0.257M / 4.67M |
| 卡西米尔 | KAZ-F | 19.27M / 23.68M | 21.02M / 25.43M | 21.09M / **25.50M** |

读法：

- **叙拉古在 R20 就已经进区间**（25.9M），R20→R40 只涨 6%——它靠「封顶值 × 次数」，封顶一抬就到位，
  层数再涨不再放大。卡西米尔同理（R20 的 19.3M 差一点，R30 起 21M 稳定在区间内）。
  **好处：前期就把强度补齐，不用等到 R40。**
- **拉特兰要等到 R40 才进区间**（R20 1.76M、R30 10.64M、R40 36.60M）：它的乘区是 `0.1%×L`，
  且搭裆（谢拉格/奥术）的层数曲线在 R40 更陡。若希望 R30 也进区间，系数要抬到 ~0.15%/层，
  但 R40 会到 ~55M（超 40M 上限）——**「早强晚超」的取舍，建议保持 0.1%/层**。

### 5.2 如果业主决定先修口径

如果业主先把 `tools/infinite-anchor-pairs.mjs` 的 `bondState()` 改成真机分档（`tier = 达到的 thresholds 个数`）
再重跑，那么推荐值需要重标定：

- 拉特兰 **LT-C′**（0.05%/层）→ 真实口径 4.06M，已是他能拿到的最好一档（弹药吞吐锁死，无法再高）；
- 叙拉古 **SIR-A+B** 不受影响（27.19M 就是真实值）；
- 卡西米尔 **KAZ-F** 会把真实口径从 0.257M 拉到 21.09M，全表最弱变成「炎 1.89M / 拉特兰 5.89M」。

也就是说：**修口径之后，「20–40M」这个目标对拉特兰就不成立了**——除非愿意让拉特兰变成全队乘区（LT-C）。
这一点需要业主拍板，本文件两个版本都给了数（LT-C / LT-C′）。

### 6.1 文案落地方式（推荐：`inf` 覆盖块）

现在 `data/bonds.json` 的每条记录可以带 `zj`（炸惊）和 `ann`（湮灭）覆盖块，

战斗与界面共用同一份实现。超限没有对应的块，**建议加一个 `inf` 块**（语义完全一样）：

- `shared/zjBonds.js`：`overlayBondRecord` / `bondIdsWithBlock` 已泛化，无需改逻辑；
- `server/sim/content/support/index.js`：照着 `setZjView` / `withZjView`（[support/index.js:57–80](server/sim/content/support/index.js#L57-L80)）
  加一个「超限视图」，`bondRecord()` 的优先级 `inf > zj > gameData()`；
- 好处：普通模式读到的 desc 逐字节不变，`inf` 块只写新增行（不用重复原文 4 行），
  diff 最小、回滚最容易。若业主不想动这块机制，就按本文件给的「完整新 desc」直接改基础记录，
  但**普通模式的盟约弹窗会显示超限专属行**——这一点必须提前说清。
