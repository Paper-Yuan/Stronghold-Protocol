## 1. 三条口径怎么落到引擎里（先定路径，再谈数）

### 1.1 外援主 C：**有**合法入口 —— 自选槽 + 变形同构体「转职」

先说结论：**引擎里确实有「把单个干员归到指定盟约」的合法入口，不需要伪造 `bonds` 计数**。链条如下（都是现读代码）：

1. **自选干员是槽位，不是普通棋子**：`data/chess.json` 里 `isDiy === true` 的 8 条 `chess_char_{5,6}_diy{1,2}_{a,b}` 是空槽
   （`stats: null`）。`server/sim/battle/players.js:162`：`if (def.raw?.isDiy && !def.diyFor) { log('自选 slot … without a pick'); return null; }`
   —— 实测把同一条目换成「不填 pick 的自选槽」直接 **0 人上场**（该行 `return null` 被触发）。所以外援必须带 `diy: { charId, skillIndex }` 入场，
   这就是生产路径 `simdata.getChess(slotId, { diy })`（`test/helpers/battleHarness.js` 的 `diy` 入口，我用的是同一条）。
2. **它自己的盟约**来自被选中的干员：`shared/diy.js:257`
   `composeUnitRecord(..., { bonds: diyOf(data)?.operators?.[charId]?.bonds ?? null })`。
   也就是说「自选干员属于哪些盟约」= `data/backups.json` 的 `diy.operators[charId].bonds`，**槽位本身没有盟约**。
3. **转职 = 变形同构体**：`data/items.json` 的 `chess_item_6_09_e_b`（变形同构体，进阶）`canGiveBond: true`。
   `shared/plugins/rules.js:220 grantedBondsByMorph`：官方档（缺省）要求**一行 ≥ 2 件、且其中一件 canGiveBond**，
   于是携带者额外获得**其余各件 `giveBondId` 写的盟约**。
4. **战斗内怎么算成员**：`server/sim/content/support/index.js:329 unitBonds(u, battle)` =
   棋子自身 `def.bonds` ∪ `grantedBondsByMorph(items, …)`（另有 annBonds / 炸惊装备组合，与本口径无关）；
   `isMember()` 再用它判「这名干员吃不吃这条盟约」。`server/sim/content/bonds/core.js:32` 原话：
   *"Members = support.isMember (own bonds, 变形同构体, 调和)"*。
5. **人数（count）**：`bonds` 状态里的 `count` 是玩家级整数，`reached()` 拿它比 `power_bond_char_cnt`；
   本脚本按**真实成员数**算（`countsFor()`），外援因为它经第 4 步真的成了锚的成员，所以**只给锚 +1**，
   其余盟约一条都不加（详见 §2 的「零污染」筛选）。

所以每套队伍的组成是：**7 名常驻（交集优先、按 v2 的分格分配）+ 1 名外援**，
外援带 `[锚的族装备, chess_item_6_09_e_b]` 两件 —— **族装备那件就是「转职」的凭据**（它的 `giveBondId` 就是锚）。
8 条大盟约各自的族装备（`data/items.json`；一律普通档 `_a`，唯一的例外是维多利亚 —— 它的族装备就是那把锤，
按业主口径用进阶金锤 `_b`）：

| 锚 | 转职用的族装备 | 效果（普通档） |
| --- | --- | --- |
| 谢拉格 `kjeragShip` | `chess_item_5_02_e_a` 谢拉格不融冰 | 攻击 12% 概率 1.5 s 寒冷 |
| 阿戈尔 `egirShip` | `chess_item_3_07_e_a` 阿戈尔重刃 | 攻击力 +40%，攻速 −10 |
| 萨尔贡 `sargonShip` | `chess_item_2_04_e_a` 萨尔贡浓茶 | 技力自然回复 +0.15/s |
| 维多利亚 `victoriaShip` | `chess_item_1_01_e_b` 维式重锤（**金锤**） | 攻击力 +25% |
| 炎 `yanShip` | `chess_item_3_04_e_a` 炎国短刀 | 每次开技能 +5% 攻击力（≤10 层） |

### 1.2 维多利亚：全员 1 把金锤

`installVictoria`（`server/sim/content/bonds/core.js:303`）有两处吃装备：主倍率 `base_damage_scale + 0.008×层数`
只作用于 `itemsOf(u).length >= 1` 的成员（裸装整条空转，这正是当初「每人 1 件锤」的由来）；6 人档再按件给
`atk_normal_equip 0.5` / 金件 `atk_golden_equip +0.3`（即金件 0.8）。

本轮口径：**凡 `data bonds` 含 `victoriaShip` 的干员，普锤 `chess_item_1_01_e_a`（+15% 攻击）换成
进阶 `chess_item_1_01_e_b`（+25% 攻击）**；外援在维多利亚阵容里转职后就是维多利亚成员，同样带金锤。
「金锤 ×8」（整队 8 件全金锤）的另一种读法也实测了，两种差多少见 §6.2。

### 1.3 拉特兰：锁「高层精准」

锚定脚本里**没有**给拉特兰锁搭档（66 组照跑），锁的是「读法」：报告与图里把**含 `preciShip` 的最好一组**
标成「锁精准」，并把**旧 Top1 搭档（谢拉格 + 奥术）**在新口径下的数也并列出来 —— 两种读法都能核（§7）。

## 2. 外援主 C 用的是哪个 `chess_diy_*` id

### 2.1 10 条 `isDiy` 的拆解

| id | 是什么 | 能不能当外援 |
| --- | --- | --- |
| `chess_char_5_diy1_a/_b`、`chess_char_5_diy2_a/_b`、`chess_char_6_diy1_a/_b`、`chess_char_6_diy2_a/_b` | 8 条**自选槽**（5 / 6 各 2 对，`_b` = 进阶档 E2 Lv60、技能 7、模组 1 段 / 3 段） | ✅ 必须带 `diy: { charId, skillIndex }` |
| `chess_chen3_a`、`chess_chen3_b`（赤刃明霄陈） | `isDiy: true` 但**不是槽**：有真实属性（`_b` 攻击 760）与固定盟约 `[yanShip]`，没有 pick | ⚠️ 能直接上场（实测 1 人、`bonds=[yanShip]`），也能再挂转职 → `[yanShip, kjeragShip]`；但它的 `yanShip` 是**自带、改不掉**的，会给每一套队伍白送 1 个炎成员，污染跨锚对比 → **不用** |

### 2.2 筛选依据（三个条件）

1. **合法**：pick 必须在 `backups.diy.ownedPool`（72 人）里，且 tier-6 槽的两档形态都存在
   —— `shared/diy.js checkDiyPick` 对 72 人**全部 `ok`**（72/72 通过，且都在 `KITTED_CHARS` 里，有 kit）。
2. **零污染**：它**自己的盟约**不能落在锚定池的 13 条（8 大 + 精准/迅捷/灵巧/奥术/不屈）里，否则它会顺手给别的
   盟约 +1 个人数，跨锚对比就掺了杂音。→ 只要 `bonds ⊆ {emptyShip}` 等池外盟约的人。
3. **够格当主 C**：按**引擎实测的单兵 DPS**（60 s、1e12 血 ELITE 木桩、1 普锤、只开 `suntShip`）排序，不看面板。

## 3. 引擎证据：外援被归到锚之后，人数与激活怎么算

同一支 7 人谢拉格队 + 同一名外援，**只换「带不带变形同构体」**，其余（人、位、装备的族件、层数、木桩）全同。
下面是从战斗里直接打出来的（`unitBonds()` / `isMember()` 是引擎自己的函数，不是脚本自算）：

```text
===== 对照：外援主 C 不带 变形同构体 =====
  # defId                diyFor               items                         bonds                     isMember(kjeragShip)
   1 chess_char_1_02_b   -                    chess_item_1_01_e_a           [kjeragShip,steadShip]    true
   2 chess_char_2_05_b   -                    chess_item_1_01_e_a           [kjeragShip,victoriaShip] true
   3 chess_char_3_11_b   -                    chess_item_1_01_e_a           [kjeragShip,preciShip]    true
   4 chess_char_3_14_b   -                    chess_item_1_01_e_a           [kjeragShip,visiShip]     true
   5 chess_char_3_20_b   -                    chess_item_1_01_e_a           [kjeragShip,deputShip]    true
   6 chess_char_4_13_b   -                    chess_item_1_01_e_a           [kjeragShip,skillfulShip] true
   7 chess_char_4_22_b   -                    chess_item_1_01_e_a           [kjeragShip]              true
   8 chess_char_6_diy1_b chess_char_6_diy1_a   chess_item_5_02_e_a           [emptyShip]               false   ← 只带族装备，不授予盟约
  场上人数 n=8   全队 DPS=93160

===== 外援主 C 带 变形同构体（转职生效） =====
   1..7 同上
   8 chess_char_6_diy1_b chess_char_6_diy1_a   chess_item_5_02_e_a+chess_item_6_09_e_b   [emptyShip,kjeragShip]  true  ← 转职生效
  场上人数 n=8   全队 DPS=142467
```

读法：

* **人数**：两种情形都是 8 人（7 常驻 + 1 外援），外援的 `defId` 是槽位 `chess_char_6_diy1_b`、`diyFor` 指向基础槽
  `chess_char_6_diy1_a` —— 这就是引擎认的「自选干员」形态。
* **成员判定**：`isMember(锚)` 从 `false` 变 `true` 的唯一差别是那件 `chess_item_6_09_e_b`；
  脚本里的 `counts[锚] = 成员数` 因此才 +1（谢拉格 7 名常驻 + 外援 = 8，脚本按真实成员数写 8，
  而 v2 的 `bondState` 对锚始终封顶 6，tier 只看 3 / 6 两档，不影响读数）。
* **激活**：`active` 由 `count >= activeCount` 决定（8 条大盟约都是 3），外援只是让「已经在场的锚」人数 +1；
  它**不会**让一条没人上场的盟约变 active —— 这也是 v2 修正过的坑。
* **DPS**：同人同位同为 8 人，只差转职 → 93.2 k → 142.5 k（这一支是 500 层口径的谢拉格队，×1.53）。
  全量扫描里的放大倍数见 §5。

### 5.2 机制：外援的收益 = 锚的乘区 × 它自己的输出；代价是少一名常驻

* **赚**：锚的倍率/真伤是**成员级**的，外援转职后就成了成员，于是吃到满倍率：
  * 叙拉古：`installSiracusa` 的「每次攻击附加 +0.5% 目标最大生命真伤（精英/首领封顶 250 万）」挂成员 →
    维什戴尔的高攻速攻击序列直接变成真伤管道，R10 **×40.8**，到 R40 仍 ×2.53（封顶开始饱和）。
  * 谢拉格 / 维多利亚：`members deal × base_damage_scale(…)`，维多利亚 500 层时 ×5.25 → 单锚基线 230.5k → 381.9k（×1.66）。
  * 拉特兰 / 炎 / 卡西米尔：锚的加成偏「给成员加攻/加弹药/加攻速」，外援是其中最肥的输出载体，×1.02 ~ 1.06。
* **亏**：旧 Top1 的伤害其实是**搭档**在扛，外援只归到锚、**不归到搭档**，还要占掉一格：
  * 阿戈尔 Top1 = 谢拉格 + 奥术，队伍里真正的输出是谢拉格成员（`installKjerag` 的倍率 + 6 人档冷风 × 对寒冷/冻结的
    ex 倍率）。外援占走一格 → 谢拉格只剩 3 人 → **6 人档冷风掉了**，ex 倍率整条失效 → 51.88M 塌到 4.51M（**0.09×**）。
  * 萨尔贡同理（−6%）；炎/拉特兰换搭档后仍然保住 Top1 的量级，是因为它们改用了「维多利亚 + 奥术/精准」这类
    不依赖 6 人档的组合。
* **一个反直觉但重要的结论**：**「加一名强力主 C」并不等于「普遍变强」**。在这套 8 格棋盘上，第 8 个人是
  「拿掉一名常驻」换来的；当队伍的强度来自**某条搭档盟约的 6 人档**时，这一换就是掉档，掉得比主 C 补回来的多得多。

## § 归因订正（2026-10-31）

> 本节**推翻 §5.2 对「萨尔贡 40.91M → 5.84M、阿戈尔 51.88M → 4.51M」的归因**。§5.2 原文保留（一字未改），**以本节为准**。
> 证据：真机口径实测，见 [`handoff/OVERLIMIT-BUFFS-KLSA.md`](OVERLIMIT-BUFFS-KLSA.md) §0.1(2) / §1.3 / §1.4。

### 1) 真实原因是 **tier bug**，不是「外援占格挤掉谢拉格 6 人档」

锚定脚本原来的 `bondState()` 是**按人数硬算** tier（`count >= 4 → tier 2`），而真机是
[`server/match/bondsMeta.js:211`](../server/match/bondsMeta.js#L211) 的 `tierFor()` = 「达到了几个 `thresholds`」。
拉特兰 / 卡西米尔 / 萨尔贡 `thresholds = [3,6]`、阿戈尔 `[3,5]`，所以 **4–5 人只有 tier 1、6 人才 tier 2**；
旧写法配上 [`server/sim/content/bonds/core.js:75-88`](../server/sim/content/bonds/core.js#L75-L88) `reached()` 的
`bondTier >= idx+1` 捷径，就让 **4–5 人白拿 6 人档**（谢拉格寒风、维多利亚按件加攻都属于这一类）。

| 锚 | 旧报告口径（tier bug） | 真机口径 · 无外援 | 真机口径 · 有外援 | **tier 修复本身** | **外援本身** |
|---|---:|---:|---:|---:|---:|
| 萨尔贡 | 40.91M | 6.14M | 5.80M | **−85.0%** | **−5.5%** |
| 阿戈尔 | 51.88M | 4.48M | 4.51M | **−91.4%** | **+0.7%**（外援甚至略赚） |

也就是说：**掉下来的是 tier bug，不是外援**。「外援 = ×0.14 / ×0.09」这个结论不成立——
在真机口径下外援对阿戈尔 **+0.7%**、对萨尔贡 **−5.5%**。
（§5.1 表里那两行的 `0.09×` / `0.94×` 不能读成外援效应：阿戈尔那一行的「无外援」列直接填的是**旧 Top1 的 51.88M**
（tier bug + 旧分格 `4/4/0`），不是同分格消融，所以 0.09× 是「tier bug + 分格重选 + 换人」三件事的合计。）

### 2) 为什么这两条锚的 Top1 里「根本没有寒风可掉」

- 这两条 Top1 里**谢拉格只有 3 人 = tier 1 = 没有 6 人档寒风**；
- 伤害 **89%–99% 来自「谢拉格 + 奥术」的成员**（萨尔贡自身成员只占 11.3%、阿戈尔 0.9%），真正在发力的乘区是
  **奥术的 `(1.2 + 0.01×L)`，R40（L = 1650）= ×17.7**；
- 而且**萨尔贡 / 阿戈尔与谢拉格的携带者重叠 = 0**（`data/chess.json` 现算：萨尔贡 18 名携带者、阿戈尔 17 名，与谢拉格交集都是 0），
  锚自己占 5 格之后谢拉格只剩 3 格 → **永远凑不出 6 人档**。

所以 §5.2 那条链「外援占走一格 → 谢拉格只剩 3 人 → **6 人档冷风掉了** → ex 倍率整条失效 → 51.88M 塌到 4.51M」
里，**后两环在这两条锚上不成立**：它们的 Top1 里压根没有寒风，`ex_damage_scale` 这条乘区从来没挂上过。
§5.2 末段「加一名主 C 不等于普遍变强」的**结论**仍然成立，但它的证据应当是**分格重选**与**叙拉古 ×2.53 的反面**，
而不是 51.88M → 4.51M —— 这两个数之间差的是 tier bug。
