## 3. 布局决策：为什么只展开「我方」

12 人 = 3×4。手机上如果三队都展开：

- **并排 3 列**：每列 4 格 56px = 224 宽，三列 672 + 间距 ≈ 720，塞得进 792。但每格只有 56 宽，头像 + 名字 + 状态点全挤在 56×56 里，三列一起看等于 12 个小方块，没有任何一队是「我的」，读起来比列表还慢；而且顶栏/底栏之外只剩 ~250 高，三列并排会让每队**只**有 4 个 56 的格子加标题，横向还剩 1/4 空。
- **纵向三队都展开**：99×3 + 间距 ≈ 330，加上 49 + 59 就 **> 360**，直接违反「一屏放下、不出现纵向滚动条」。

所以：主屏只给「我方」姓名级信息（56×56 × 4），另外两队各压成一行 42px 的摘要，点开才进 sheet。

折叠行里保留的东西（缺一不可，否则不知道点进去值不值）：

```
○ 蓝方同盟            ✓ ✓ ✓ ✓   4/4  已就绪   ›
   ↑ 同盟标记         ↑4 席状态点  ↑占位   ↑满员全就绪才出现
```

- 4 个状态点复用同一套记号：`●`在线 `✓`已就绪 `◌`空位 `⚠`掉线（纯 CSS 画，不依赖字体里的符号）。
- 「已就绪」只在 4/4 全就绪时出现（红方 1/4 只给点，不写「未就绪」——省 4 个字的宽度，也省一条新文案）。

桌面不做折叠：1920 有宽度，三列并排一次看全 12 人，右栏给房间信息/规则/聊天。

## 6. 与任务书的三处偏差（都不改硬约束，请看一眼）

1. **56×56 格里怎么放名字**：任务书写「头像 + 单行省略名字 + 状态点」。稿里名字压在格子底部的渐隐条上（9px、`text-overflow: ellipsis`），状态点挂右上角 —— 不是「头像下面另起一行名字」。理由：另起一行要多 12–14px，主屏就要从折叠行的呼吸里抠出来。72/96 的格子同样处理。
2. **桌面每队标题里的 `n/4` 用「占位数」**：任务书 C 写的是「就绪进度条 3/4」，但如果标题放占位、进度条放就绪率，同一队会出现两个分数（我方 3/4 占位 / 1/4 就绪），读起来打架。现在统一成：**标题的 n/4 = 占位数**（与顶栏 8/12 同一口径），**就绪率只给 4 段状态条 + 每席的点/字**，不写第二个分数。要「就绪 3/4」这种数字的话得定一个口径，见 §7 第 3 条。
3. **开始按钮的视角**：按任务书画的「未满员 → 开始模拟置灰」。但这张画的视角是「我方队长」，不是房主；仓库真实现里非房主只看到准备就绪。见 §7 第 2 条。

其余都照做：类名沿用 `.rs-top/.rs-exit/.rs-clock/.rs-tools/.rs-seats/.rs-foot/.rs-pill/.rs-ready/.proto-start` 这一套（连 `--rs-lit #4fe8c0`、掉线红 `#ff7a8a`、空位加号、房主 mint 实底徽标都是 room.css 的原值），眉题 + 8% 底图少量呼应启动页稿，没有扫描线/呼吸光/编号这些装饰（信息密集页，克制）。

## 7. 需要你拍板的点

1. **12 人房没有「房间名」这个数据**。仓库里房间靠 6 位密钥 + 模式名标识（`room.code`），顶栏本来就是模式名。稿里标题位放的是「同盟模拟」+ `8/12`。12 人房要不要引入真正的房间名（新字段 + 新输入框）？还是维持现在这样？
2. **开始按钮归谁**：房主独占，还是各队队长也能开？现在画的是「我方队长视角 + 未满员置灰」。如果只归房主，我方这一栏应只剩「准备就绪」，开始按钮整个不出现。
3. **每队那个分数的口径**：`n/4` 是占位数还是就绪数？（现稿=占位数，与 8/12 一致；就绪率只用点/条表达。）如果要同时显示两个数，得先定哪个是主数字。
4. **「房主」还是「创建者」**：仓库现成词是「创建者」（room.js 座位卡）。用「房主」= 新词 1 条。我按任务书用了「房主」，但 56px 的格子里只能挂「队长」，房主徽标只出现在 sheet（72）和桌面（96）——要不要统一回「创建者」？
5. **掉线席位的「保留多久」提示放哪**：建议放「我方同盟」面板右下角（主屏那块 764 宽的空白正好在那儿），HTML 里已经用注释留了占位（没有画任何字）。备选：折叠行尾部、或点开 sheet 时在标题旁。**文案目前也不存在**（「掉线」本身还是新词），要一起造。
6. **「8/12 未满员」的置灰理由没有现成文案**：仓库只有「仍有博士未准备就绪」「等待所有博士准备就绪」，都不准确（真正的理由是缺 4 个人）。要不要补一条？（候选：`仍未满员` / `等待博士加入`，都需新增 msgid。）现在手机上没写理由，只靠顶栏的 8/12 + 置灰本身表达。
7. **sheet 在 792×360 下两侧是空的**（名册块只占中间 220×190）：接受这种克制，还是把「关闭」挪到右上角、名册改成一列 4 行（每行 72 头像 + 名字/状态在右）把横向用满？

### H.3 联防条为什么放在「顶部状态条下方」

四个理由（按权重排）：

1. **同一层信息放一起**：联防是**整局/整轮**级别的状态（和顶部「两队/三队状态条」同级），不是某个人的局部信息。放在状态条正下方，顶部就成了一条「全局信息带」——从上到下**一眼读完**（队级状态 → 联防阶段 → 棋盘），视线不用来回跳。
2. **底部已经满了**：左下是我方 4 人血量条（y319–350）、右下是聊天球（y304–350）。40 高的联防条若压在底栏上方（约 y262–302），会**紧贴血量条上沿**、并与聊天球同高，三条不同性质的信息挤进同一个 40px 带子里互相抢；顶部没有这个冲突（y14–18 有 4px 呼吸，下面到棋盘之间还空着）。
3. **顶部是「只看」、底部是「会点」**：底部是拇指区（芯片、聊天），联防条本期**不可点**（没有新交互），不该占操作热区；顶部纯读，正好。
4. **数字常驻可见**：`剩余敌人 6` 是这一屏唯一会跳的数字，放顶部不会被手指/棋盘中心挡住，也不压住棋盘底部的部署格示意。

### H.10 与口径的 6 处取舍（都只影响观感，请看一眼前 3 条）

1. **芯片上不写队名**：36×36 里只有队色条 + `n/4`（+ 掉线 `▲`）。8 人房的「对方 / 我方」在未点开时**只靠颜色区分**，队名出现在点开后的浮层抬头；12 人房同理。要队名常驻，得把芯片从 36 加宽到 64+（会改变左栏占位），这不是本单能自行改的口径。
2. **血量只用条、不出数字**：26×26 的头像条里塞不下「8/10」，数值放在 `aria-label`。要可见数字需要把队友格加宽到 32–40（一行 CSS），或改成悬停/点开才显示的浮层。
3. **顶部状态条 = 席位在线状态（4 格），不是队伍总血量**：别队**只给队级状态、不给数值**是按你的前提做的；但我没有把「队伍总血量」这个概念画出来（仓库里也没有这个数），四格是**席位**（在线 / 掉线 / 缺位），与芯片的 4 段队色条同一套语法。
4. **联防条的三段信息 = 4 条既有 msgid**：`联防阶段` + `联防：{names}` + `剩余敌人 {v}` + `联防中`。没用「`联防阶段：{names} 迎战突破防线的敌人`」是因为它和旁边两段重复、且条内会挤；要换是一行 markup。
5. **成功 / 失败态没进图**（本单只要三张）：换法是同一个条、同一个位置，只把状态格换成 `成功` / `失败` 并加 `.is-done` / `.is-fail`（`联防中` 那个 class 去掉），计数归 0；三段布局与 rect 不变。
6. **联防条不可点**：本期没有「进入联防 / 退出联防」这类新交互（玩法零改动），所以条上只读；如果日后要做成可点，最小边已经够（40 高），不需要改版式。
