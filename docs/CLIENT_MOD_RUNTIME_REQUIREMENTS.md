# 卫戍协议全量 MOD 加载（多端运行时）技术要求规范

> 适用端：PC 浏览器端 / Android 手机真机端 (Capacitor/WebView) / 本地联机服务端 (Node.js)  
> 目标级别：**全量 MOD 加载**（含干员、地图、敌人、波次、装备、盟约、音频、图片与行为层 Kit 脚本）  
> 执笔：石井 | 架构与安全研究

---

## 一、 硬件与系统环境要求

| 维度 | PC 桌面端 (Chrome / Edge / Firefox) | Android 手机真机端 (APK / WebView) |
|---|---|---|
| **系统版本** | Windows 10/11，macOS 12+，Linux | **Android 8.0 及以上** (API Level 26+) |
| **WebView 内核**| Chromium 105+ 或对应现代浏览器 | **Android System WebView 105+** (要求支持 Web Streams API 与 DecompressionStream) |
| **运行内存 (RAM)**| 建议 **4GB 及以上** (全皮肤 Spine 贴图与多语音需一定显存) | 建议 **3GB ~ 4GB** (全皮肤高精贴图需要充足堆内存) |
| **存储空间 (ROM)**| 剩余 **2GB 及以上** | 剩余 **2.5GB 及以上** (170+ 套全皮肤 Spine + 双语 5000+ 音频文件占用) |
| **网络环境** | 本地联机 / 局域网 / Cloudflare Tunnel | 支持离线单机运行；联机时要求建立 `adb reverse tcp:3000 tcp:3000` 或局域网直连 |

## 二、 客户端能力与接口硬性要求（六层核心通道）

要实现“全量 MOD（含全皮肤、全语音）”直接跑，客户端与引擎必须满足以下 6 大功能要求：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   全量 MOD 客户端六层通道 (含全皮肤全语音)              │
├─────────────────┬──────────────────────────────────────────────────────┤
│ 1. 存储层       │ IndexedDB (sp_mod_storage) 单库配额需支持 200MB+     │
│ 2. 数据层       │ data.js 拦截器支持内存动态 mergeCustomContent        │
│ 3. 资源层       │ 自动将 ZIP 提取的图片 Blob 转化为 ObjectURL 注入图鉴 │
│ 4. 皮肤层 (Skin)│ Spine 骨骼管道支持动态换装 + 房间选皮同步广播       │
│ 5. 语音层 (Voice│ Web Audio / Howler 挂接 12 大槽位，支持 CN/JP 切换   │
│ 6. 行为层 (Kit) │ sim 战斗引擎必须打通 kits/<id>.js 动态安全执行器     │
└─────────────────┴──────────────────────────────────────────────────────┘
```

### 1. 存储层要求：必须使用 IndexedDB，严禁 localStorage
- **原因**：全量 MOD 包含 170+ 套皮肤 Spine 图集、高精立绘及 12 个槽位的双语 MP3，体积可达 50MB ~ 200MB。`localStorage` 仅有 5MB 限制，必须走 IndexedDB 物理存储。
- **现状**：客户端已实装 `modStorage.js`（基于 IndexedDB），本项已满足。

### 2. 数据层要求：离线单人模式必须具备本地 Overlay 拦截
- **要求**：当玩家在手机端断网/单机飞行模式启动游戏时，客户端 `public/js/data.js` 的 `readJson()` 必须自动读取本地已激活的 MOD 数据并执行增量合并。
- **现状**：联机房间已由服务端自动合并生效；手机离线单机模式需补充 `public/js/data.js` 本地拦截即可达到 100% 独立离线。

### 3. 素材层要求：Blob ObjectURL 动态挂载
- **要求**：MOD 中携带的 `art/*.png` 或 `assets/item/*.png`，客户端解包后需提取为二进制 `Blob`，并通过 `URL.createObjectURL(blob)` 注册到全局资源解析器（`artResolver`）。
- **目的**：确保离线或无外网图床时，自定义装备图标与盟约徽记不会变成空白或裂图。

### 4. 皮肤层要求：Spine 骨骼按需加载与头像同步
- **要求**：
  - 皮肤 Spine 必须包含完整的 `Idle`, `Attack`, `Die`, `Default` 动作骨骼三件套（`.skel`/`.json` + `.atlas` + `.png`）；
  - 图集贴图分辨率严禁超过 `2048×2048`；
  - 房间与战局必须通过 `room.skins` 广播玩家所选皮肤，队友屏幕实时可见对应立绘与小人换装；
  - 手机端必须实行**按需加载（On-demand load）**，严禁一次性预加载所有皮肤引起 GPU 显存 OOM 崩溃。

### 5. 语音层要求：12 大战术槽位与多语言无缝切换
- **要求**：
  - 音频引擎（`public/js/audio.js`）必须支持标准 12 个槽位（`start`, `faceEnemy`, `select`, `place`, `skill1~4`, `resultFour~Lose`）；
  - 支持双语/多语种动态切换：默认日语（`jp`）与国语（`cn`），玩家切换语言时自动无缝从 `voiceLangs` 播放；
  - 音频编码硬性要求：必须为标准 **MP3**（比特率 64~128kbps）或 **OGG**，单文件控制在 200KB 内，严禁塞入未压缩 WAV 无损大音频。

### 6. 行为层 (Kit) 要求：战斗引擎必须接入安全脚本执行器
- **要求**：
  - 战斗模拟器（`server/sim/` 与 `public/js/sim/`）在结算干员技能与天赋时，必须支持动态导入 `kits/<chessId>.js`；
  - 必须提供沙盒隔离，仅开放官方 36 个合法事件钩子（`onCast`, `onHit`, `onKilled` 等），拦截一切非法 DOM 与网络越权。

## 三、 对分发 MOD 包的格式要求（合规要求）

任何想要被你的客户端“一键直接加载”的 MOD 包，必须符合以下结构规则：

1. **统一文件格式**：`.spmod` 或标准 `.zip`；
2. **禁止多层嵌套**：解压后的根目录（或第一级目录）必须平铺放置核心文件，**严禁使用带安装脚本的整文件覆盖包**；
3. **必需具备清单文件**：
   - 必须包含合规的 `pack.json`（标明 ID、版本、适用的游戏版本 `app: ">=0.2.0"`）；
   - 必须包含 `README.md`（供手机与电脑端模组管理器提取卡片简介与更新日志）；
4. **命名空间隔离**：
   - 干员 ID 必须携带 `_ws_` 标签（如 `char_ws_my_op`）；
   - 装备 ID 必须以 `chess_item_ws_` 开头；
   - 严禁擅自使用与官方原版干员冲突的纯数字 ID。
