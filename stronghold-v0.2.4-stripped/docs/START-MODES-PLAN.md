# 起始三档 · 实施计划

三档按**角色**切，不按传输切：①自己玩 ②开服给同伴 ③去加朋友。代码上只有两个形态——本机引擎 / 别人的引擎；①②的差别不是网络，是"要不要把地址交给同伴"。`HOST` 一律保持 `0.0.0.0`（不再尝试回环绑定，已回档过一次）。

## 三档定义

| 档 | 标题 | 说明文案 | 实现 |
| --- | --- | --- | --- |
| ① | 自己玩 | 引擎在手机里，不联网也能打；朋友加不进来 | 已通，不动 |
| ② | 开服给同伴 | 同 Wi-Fi 里朋友只填 4 位同盟密钥；UU 群加速 / Tailscale 也选这项，把下面列出的地址发给朋友 | **缺地址列表**（下） |
| ③ | 去加朋友 | 粘贴房主的地址或邀请链接：`192.168.x.x` 同 Wi-Fi、`100.x`/`10.x` 虚拟局域网、`https://域名` 远程服务器都填这里。自己开服别选这项 | 两处必改（P0） |

## UU 群加速为什么现在只能填地址

链路应为：房主②→看到自己的虚拟局域网地址→发给同伴→同伴③→粘贴→进游戏只填 4 位码。断在第一环：

- `android/.../NetworkUtils.kt:11` 的 `IGNORED_IFACES` 含 `tun0`/`tap0`/`ppp0`，`:44` 跳过；`:48` 还要求 `isSiteLocalAddress`（只认 10/8、172.16–31、192.168）。→ **房主界面永远只印 Wi-Fi 地址**，UU 分配的地址根本不显示。
- 同伴侧自动发现（`:73-94` 逐 /24 扫 + `:97` 打 `/lan/room`）在非 /24 的虚拟网段必不成立。
- 若 UU/Tailscale 发 100.x（CGNAT），服务端 `isPrivateAddress`（`server/index.js:324-336,711`）也回 404，扫到也用不了。

## 改动清单

**P0（不改则③档域名和②档 UU 都用不了）**
1. `MainActivity.kt:698-715` `normalizeServerUrl`：`:714` 无端口一律补 `:3000`，会坏 `https://域名` → 有 scheme 无端口时不补。
2. ②号卡增加"本机全部 IPv4 候选"列表（Wi-Fi 与虚拟网卡分开标、带端口、逐条复制）。新增一个不过滤的 `allAddresses()` 即可，**扫描逻辑不动**。

**P1**
3. 存 `server_role = solo|host`：`MainActivity.kt:722` 只按 `remote/local` 决定预选，房主下次打开会跳回"本机单人"。
4. ②号卡的邀请链接别用 `location.origin`（`public/js/screens/room.js:71-75`）：APK 内复制出来是 `http://127.0.0.1:3000/?room=XXXX` 死链，需 shell 覆写。
5. `public/js/screens/lobby.js:248-256`：连着远程服时仍拿本机网卡扫描，会误报"两台设备不在同一网络" → 按 origin 分流，非本机提示改为"这台服务器上没找到密钥 XXXX…"。
6. 端口目前安卓侧写死 3000（`NodeServerService` setenv、健康探针、扫描器默认值），与"动态端口"的既定方向未落地；UU/Tailscale 场景房主换端口即全断。
